## Commands

Run everything from the repo root. You need Node ≥ 22.12 and npm workspaces.

| Command | What it does |
|---|---|
| `npm install` | Install all workspaces |
| `npm run dev` | Start the Vite dev server for the client (http://localhost:5173); local solo mode unless `VITE_SERVER_URL` is set |
| `npm run dev:server` | Run the game server with reload (ws://localhost:8080; allows localhost:5173/4173) |
| `VITE_SERVER_URL=ws://localhost:8080 npm run dev` | Client in online mode (lobby) against the local server |
| `npm test` | Vitest across all workspaces: unit tests, headless balance runs, the 3-bot server integration test |
| `npm run test:e2e` | Playwright browser tests (`apps/client/e2e`): builds `apps/client/dist-e2e` with `--mode e2e`, then runs portrait iPhone / Pixel emulation, desktop and PWA tests in Chromium, and last, alone (the `perf` project waits for the others), the 300-creep stress test (~4 min); `?lab&auras` starts heroes with E learned |
| `npm run build` | Typecheck every workspace (`tsc`), build the client to `apps/client/dist`, bundle the server to `apps/server/dist/index.cjs` |
| `npm run loadtest [-- --url wss://… --origin …]` | Ramp full rooms (3 bots each) until the server's average tick exceeds 10 ms (see docs/DEPLOY.md §6) |
| `npm run typecheck` | Typecheck only |
| `npm run preview` | Serve the production build locally |
| `npm run balance [quick] [solo\|teams\|2p\|3p] [seeds…]` | Print solo balance-bot and idle-bot results for every hero, plus mixed teams (three 2-bot pairs, 3 bots), with Heart HP lost per third of the match, towers branched, each hero's R casts and each player's unspent gold at the end, in Full mode (or Quick with `quick`); use it after editing `tuning.ts` or `bots.ts` |
| `npm run balance:matrix [-- quick\|full] [normal\|hard] [novice\|casual\|expert] [solo\|pairs\|trio] [--team ranger,warden] [--seeds N] [--jobs N] [--json file] [--tuning '<json>']` | The balance matrix: every bot on Normal and Hard, Full and Quick, solo (each hero), each pair and three players, over seeds 1..30, one table per bot / mode / difficulty: win rate, Heart left (mean, lowest, highest), share of the Heart lost per third, Heart lost to flyers (per lane), hero deaths (the Warden's), R casts, kills and damage per cast, combos, ultimates' share of all damage, towers. About 2,500 matches (25 min on 4 cores); filter it and use `--tuning` to try a number without editing `tuning.ts` |

## Architecture rules

- **The sim is pure and deterministic.** `packages/sim` has no DOM, no Node APIs and no networking. Its tsconfig uses `lib: ES2022` and `types: []`, so using them fails to compile. It uses a fixed 20 Hz timestep (`TICK_RATE`) and the seeded RNG in `rng.ts` (state is kept in `GameState.rng`). **Never** use `Math.random()`, `Date.now()` or `performance.now()` in `packages/sim`; a test enforces this.
- **The sim API** is `createGame(config, seed)`, `applyCommand(state, playerId, command)`, `step(state)` and `snapshot(state)`. The state is a plain, mutable, JSON-able object. `snapshot()` never mutates it. Hosts also call `setPlayerConnected` (drop / rejoin) and `setPlayerLeft` (gone for good: their empty pads open to everyone).
- **Match modes are tuning.** `createGame(config, seed)` takes `config.mode` (`full` default, or `quick`) and stores `tuningForMode(tuning, mode)` in `state.tuning`: the engine only ever reads `state.tuning`, never the mode. Mode numbers live in `TUNING.modes.<mode>` (partial `economy` / `waves` / `playerScaling` / `hero.xpForLevel`). Code outside the sim that needs a mode's numbers (bots, HUD) calls `tuningForMode(TUNING, snap.mode)`.
- **Maps are data.** A map is a `MapData` object (`src/maps/*.ts`): size, lanes (waypoints, portal first, Heart last), Heart, hero spawn, pads with zone tags (`west` / `mid` / `east`, `extra` for 3-player teams), pad size and the safe-zone row. `buildMap` derives the tile grid; `getMap()` returns Spire. Never hard-code map coordinates in engine code or bots: derive them from the map (lanes, `heroSpawn`, pads).
- **Team size:** a match holds **1–3 players, one per lane** (`MAX_PLAYERS` in the protocol): rooms answer a 4th join with `room_full` and `createGame` throws on more. Per-team-size tuning tables (`playerScaling`, `pads`) have 3 entries.
- **Pad zones:** `padLayout` decides which pads exist for a team (base pads, plus `tuning.pads` extra pads per lane zone by player count) and who owns them (solo: all; 2 players: West + west half of Mid / East + east half; 3: West / Mid / East). `state.pads` / `snapshot.pads` hold `{ id, owner }` (owner `null` = open to all). `build` is rejected on pads that aren't in the match or belong to a teammate.
- **Hosts run matches through `Match`** (`match.ts`): `createMatch(config, seed, build)` (the host's git commit or `dev`, stamped into the report and replay: the server's `RENDER_GIT_COMMIT` via `ServerConfig.build`, solo the client's `VERCEL_GIT_COMMIT_SHA` via Vite's `__BUILD__`), `matchCommand` (rounds command coordinates to 1/100 tile, logs `[tick, player index, type, …args]`), `matchPresence` (`join` / `drop` / `leave`, logged too) and `matchStep` (also counts the report's numbers). Everything the host applies goes through them, in the order it applies it, so `replayMatch(matchReplay(m))` re-runs to the same state (the server integration test checks it). When the match ends the host sends `{ t: 'report', report, replay }` once (the server again to a player who rejoins after the end) and the server logs `reportSummary`. Headless balance runs and bots still call `applyCommand` / `step` directly.
- **Events:** sim code emits into `state.pendingEvents`. At the end of `step()` they move to `state.events`, which the next `snapshot()` carries. Hosts apply commands, then `step`, then `snapshot`.
- **The client never mutates game state.** It sends `Command`s through a `Transport` and renders `Snapshot`s. Your own hero is the one exception to *where* things are drawn: while the joystick or a move order steers it, `HeroPredictor` (`predict.ts`) draws it walking at once along the sim's path and blends it back to the snapshots (jumping only past 1.5 tiles); the server stays authoritative. Everything else is drawn from the interpolation buffer. Client-only UI state (input mode, selection, markers) lives in `uiState.ts`.
- **Transport:** `LocalTransport` runs `SimHost` in a Web Worker; `NetworkTransport` talks to the game server. Both exchange *encoded* protocol messages and both deliver complete `{ t: 'snapshot' }` messages to the game view. `NetworkTransport` rebuilds them from keyframes + deltas, so the renderer and HUD never see deltas.
- **The server is authoritative.** Each room owns the only real `GameState`. Commands are queued as they arrive and applied at the start of the next tick, in arrival order; then `step`, `snapshot`, and a broadcast (a full snapshot for new or reconnected clients and every `keyframeEveryTicks`, otherwise one encoded delta shared by all clients). Never trust anything from the client beyond a decoded message.
- **Rooms are self-contained** (lobby, sim, sockets in one process). Room codes start with the server's `SHARD` letter so a future router can route by code (docs/DEPLOY.md §7). Keep Render at one instance per shard.
- **Server config comes from env** (`config.ts`). Tests build configs with `defaultConfig({...})`, e.g. `tickMs: 1` to run game time fast.
- **Damage:** every hit goes through `damageMultiplier` (`combat.ts`): physical is reduced by armour, magic by magic resist, for creeps, heroes and towers alike. Creeps carry their current `armor` / `magicResist` (bosses change theirs). Bosses are creep kinds with `boss: true`; test for the flag, never for a kind name.
- **All balance numbers live in `packages/sim/src/tuning.ts`.** Durations are in seconds, distances in tiles and speeds in tiles/s. Convert with `secondsToTicks`. Don't scatter constants. Hero skills live under `tuning.hero.<kind>.<skill>`, with per-rank arrays (4 entries for Q/W/E, 3 for R). Q and W cost mana; ultimates (R) have no `manaCost` (cooldown only). Mana regen is `manaRegen + manaRegenPerLevel × (level − 1)` plus Clarity Aura.
- **Hero skills:** `skills.ts` owns every Q/W/E/R (`SKILL_MODES` says instant / point / passive). A new skill needs its tuning, a case in `skillInfo`'s tables and `castInstant` / `castAtPoint`, display text in `apps/client/src/heroInfo.ts`, and a test in `packages/sim/test/heroes.test.ts`.
- **Units:** the sim works in tiles (floats). The renderer multiplies by `TILE_PX` (32). Pads are `map.padSize` tiles square (3 on Spire).
- **Layout and touch (docs/MOBILE.md §4–5):** `computeLayout` decides everything about the screen (tall / wide / rotate, tile size, control positions, follow range) from the viewport, safe-area insets, touch and orientation; `GameView` applies it. Top bar is 44 px (the map must fit 412 × 839). Keep layout and gesture rules as pure functions in `layout.ts` / `touch/gestures.ts` with unit tests; `touchControls.ts` only wires them to DOM and pointer events. Canvas input splits by pointer type: mouse → `Controls`, touch / pen → `TouchControls`. Radial menus in the tall layout and on touch screens, desktop panels otherwise. The controls must never cover gameplay (lanes, pads, Heart) and radial menus must never cover the controls; the layout and e2e tests check both.
- **PWA:** the service worker is generated by `vite.config.ts` and only serves same-origin GETs (never the WebSocket). Solo pause is a worker control message (`{ ctl: 'pause' }`), not a protocol message. `import.meta.env.MODE === 'e2e'` code (the `window.__tdt` hook, `?lab` gold) must stay out of normal builds.
- **Art (docs/ART.md).** Everything is drawn in code with Canvas 2D and **baked once**: registered frames into the art atlas (`render/art/atlas.ts`), the ground into one canvas (`ground.ts`); Settings → Display re-bakes both in place. Each entity's art is **one file in `render/art/entities/` that calls `registerArt`**; `load.ts` globs the folder, so adding art never edits a shared list. `WorldRenderer` asks the registry (`creepArt(kind)`, `towerArt`, `heroArt`, `projectileArt`, `trapArt`) and uses a rig or a baked sprite when there is art, else the entity's shape (a distinct shape and colour); everything has an HP bar. Rigs animate by position / rotation / scale / tint / alpha only; hit flashes are a white silhouette's alpha.
- **Sound is client-only and made in code** (docs/ART.md §13): the lobby a Japanese garden, matches a Three Kingdoms war epic, original sounds and tunes only. A sound is a `SynthDef` in `audio/sounds.ts` (volume, cooldown, most voices, priority, variants, reverb send, pitch spread), baked in `bake.worker.ts`. `GameAudio` plays it from events or renderer facts (`onTowerShot`, `onMeleeImpact`) through the mix (`mix.ts`: gate, then a new `Take` each play); never play audio from the sim or bypass the gate. Muted means no audio work at all. **Recorded files** replace code-made sound with no code change: `public/music/{lobby,match,boss}.mp3`, `public/sfx/<sound id>.mp3` (docs/SOUND_FILES.md); the build lists them, the game trims their silence and levels them, and the service worker caches them on first play, never on install. A new effect needs a row in `public/sfx/README.md`.
- **Effects are client-only** (never in the sim): `WorldRenderer` derives them from snapshots (HP drops = hit flashes, new projectiles = shots) and events, and plays them through `Effects` (`render/fx/`). The sim only reports facts: damage numbers come from its per-tick `damage` events (who dealt how much to which creep), all of them solo and only yours online (`HitTracker.feed`). Everything is pooled: particles go in the four `ParticleContainer` layers via `fx.emit` / the recipes; persistent visuals (zones, Heart, portals, auras, trails) are created once and animated by transform / alpha / tint only. Mark an effect `essential` only if it shows gameplay (areas, hits); the rest disappears at Graphics → Low (`fxLevel`). Shake goes through `fx.bump`, which honours Low and the Screen shake setting. `FxLevel.calm` (the device's `prefers-reduced-motion`, re-read when the OS setting changes) is for the effects that move: the Iron Vow ring, the rain strikes and the Meteor Rain fuse burst keep their rings and flashes and drop streaks, sky, bloom, turning, blinking, embers and shake (the fuse band is DOM, `CoopStage.fuse`: its CSS fades under `prefers-reduced-motion` instead of unrolling); other effects do not read it yet.
- **The client may import static data from `@tdt/sim`:** `getMap()`, `TUNING`, `tuningForMode`, `towerTier`, `towerStats`, `TILE_PX`, `padAtTile`, and the pure map pathfinding `findPath` / `nearestWalkable` (own-hero prediction walks the path the sim will). Pad ownership comes from `snapshot.pads`. It must not call sim functions that touch game state (`LocalTransport` / `SimHost` are the exception, since they *are* the host, and so is the `?stress` scene's `StressTransport`).
- **Protocol validation:** `decodeClientMessage` rejects unknown types, extra keys, non-finite or out-of-range numbers, and oversized messages. Game-rule validation (gold, range, cooldowns, ownership) happens in `applyCommand`, which emits a `rejected` event instead of throwing.

## Conventions

- Strict TypeScript everywhere (`strict`, `noUncheckedIndexedAccess`, `noUnusedLocals`, `verbatimModuleSyntax`). Use `import type` for types.
- Workspaces export TypeScript source directly (`"main": "src/index.ts"`). There is no per-package build step; Vite and Vitest compile from source.
- ES modules, 2-space indent, single quotes, semicolons, trailing commas, ~120-column lines.
- Every sim mechanic gets a Vitest unit test. Use the helpers in `packages/sim/test/helpers.ts` (`labGame`, `placeCreep`, `parkHero`, `run`, `tuningCopy`) for isolated mechanic tests.
- **Balance targets (Spire, playtest 2; `docs/GAME_DESIGN.md` §13, `docs/balance/`):** Normal is for first-time players, Hard for players who know the game. Novice bots win at least 80% of the seeds for every team on its own (each solo hero, each pair, the three), in both modes; casual bots win with 50–90 Heart (`HEART_TARGET`); expert bots finish Normal with 85 or more (`EXPERT_NORMAL_MIN`) and Hard with 40–80 (`HARD_TARGET`); casual Hard may lose. Teams (2 and 3 players) keep the curve (last third ≥ 25% of the Heart lost, first ≤ 45%). Solo means are within 10 Heart between heroes and pair means within 12; the casual Warden dies at most 3 times a Quick match; one rank-1 rain on a Quick wave 8–10 kills the Runners, Wisps and Grunts on every lane and takes at least half the HP of the rest (Brutes and bosses aside), and takes at most about 8% of a boss (`combat.ultimateBossFactor`); casual bots in Quick average at least 10 kills per Arrow Storm and 8 per Meteor and ultimates are 8–15% of a team's damage; Meteor Rain does at least 1.5× the damage of its two ultimates cast apart, Stun Storm and Shockwave clearly more; Iron Vow heals at least 35% of max HP. **The tests** (`balance*.test.ts`, `ultimates.test.ts`, `balanceKits.test.ts`) run the 5 gate seeds (`BALANCE_SEEDS`): every match must win and the mean must sit in the band (`heartGate` in `test/helpers.ts`, a few Heart of slack, and a share of the seeds in it), because a single seed swings ±20 Heart and a per-seed band cannot hold. **The matrix is the real measurement**: after changing `tuning.ts` or `bots.ts`, run `npm run balance:matrix` (filtered to what you touched) and compare with `docs/balance/final.txt` (the earlier aimed-circle version is `docs/balance/aimed-circles-final.txt`). Cliffs: Quick pair creep HP ×1.5 → ×1.55 sent the pair of rangers from 54 to 36 Heart, Full pair late bonus 0.35 → 0.42 from 80 to 51; the ranged pair (Arcanist + Ranger) is the weakest and Warden + Arcanist the strongest composition. Hard needs a flat multiplier, never a ramp toward the last wave (a ramp makes every team end at about 100 or about 0 Heart).
- Bots only read snapshots and act through commands, never by touching `GameState`. Online, `BotClient` wraps the same bots over a real WebSocket.
- Server tests start a real server on port 0 (`test/helpers.ts`: `startServer`, `bot`, `fullRoom`). When a test speeds up ticks (`tickMs: 1`), scale `rateLimit` up to match.
- Protocol changes: update `types.ts`, the validation in `codec.ts` (and its tests), and keep `diffSnapshot`/`applySnapshotDelta` exact. `delta.test.ts` checks this over a long match. **Bump `PROTOCOL_VERSION`** for any change to messages, commands or snapshots: the server announces it in `hello` and rejects entry messages with another `v`, and the client then shows "New version available — refresh".
- Towers: per-tier numbers live in `TUNING.towers[kind].tiers` (tier 1 = build); read them with `towerTier(tuning, kind, tier)`. After the last tier a tower upgrades into one of its two branches (`TOWER_BRANCHES` in the protocol, numbers in `TUNING.branches`): tier 4, `tower.branch` set, final. The `upgrade` command carries `branch` exactly then (the sim rejects it before, and rejects a plain upgrade at tier 3). Engine code reads a tower's numbers with `towerStats(tuning, kind, tier, branch)`, which merges the branch's effects (`TowerEffects`) over plain defaults (`NO_EFFECTS`); plain-tier shots carry no `fx`, so they behave exactly as before branches. A new branch effect needs a `TowerEffects` field, handling in `towers.ts`, a stat row in the client's `towerInfo.ts` and a test in `branches.test.ts`.
- Original names and art only: no Warcraft, Dota or other studio assets or names.
- Effect colours only from `render/palette.ts` (`FX`, `COLORS`…), never hex literals in effect recipes or effect calls. UI icons are drawn in `render/art/icons.ts` (no icon packs or image files); a new tower, hero or skill needs one.
- Art: palette colours only from `RL` tokens (`render/art/tokens.ts`), drawn through the painter, light from the upper left, glow only on emitters; characters from the front (facing +x), towers and buildings from above; check the phone-size copy in `?showcase` in Normal and Bright. `test/art.test.ts` checks every entry (file named after its id, required frames, sizes, packing, no `Math.random` in art); `e2e/art.spec.ts` checks the showcase lists every file.
- Record new design decisions in the Decision Log in `docs/GAME_DESIGN.md`.
- Browser tests: Chromium only (the iPhone project emulates the iPhone's viewport, touch and DPR in Chromium). Drive touch through `Finger` (CDP touch events) in `e2e/helpers.ts`; assert on `window.__tdt.sent` (commands) and `latest()` (snapshots). After `page.goto`, call `waitForReady(page)` before touching `window.__tdt`: it waits for `<html data-ready>` (set by `main.ts` once the first screen is up), since `expect.poll` gives up at once if its callback throws. The stress test asserts JavaScript cost per frame from a CPU profile; real FPS is asserted only on a hardware GPU. In the renderer, avoid redrawing small `Graphics` every frame: in Pixi v8 each redraw rebuilds the whole draw list (use sprites, or redraw only on change).
- End each session with a summary: what was built, how to test it, and open questions.

## Deployment

See [`docs/DEPLOY.md`](docs/DEPLOY.md).

- **Client:** Vercel imports the repo root. `vercel.json` runs `npm ci` and `npm run build`, and serves `apps/client/dist`. `VITE_SERVER_URL` (build time) switches on online mode.
- **Game server:** a Render web service from the root `Dockerfile` (`render.yaml`: Singapore, `/health`, 300 s shutdown delay, one instance). `ALLOWED_ORIGINS` must list the Vercel production and preview origins.
