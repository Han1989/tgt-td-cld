## Why
CrazyGames' QA looks at a game in its own frames at one device pixel per CSS pixel, and a rejected game is taken again only with clear improvements. The advisor read their pages again on 13 Nov 2026 (a session cannot open them: treat this as the specification).
- "Text and images must be legible on devices with a devicePixelRatio:1, on responsive iframe sizes (16x9 ratio) and mobile screens." Their most important frames: desktop, not fullscreen 907 x 510, 1216 x 684, 1077 x 606, 821 x 462; desktop, fullscreen 1366 x 768, 1920 x 1080, 1536 x 864, 1280 x 720; mobile 800 x 450; tablet 1080 x 607.
- "We allow vertical/portrait games to be published", with "black bars or background images around on the sides". So the portrait map in the middle of a landscape frame is fine as it is: this task does not change the camera or the map's fit.
- "You can configure supported orientation in your submission. The website will make sure your game can be played only in those orientations." The submission says portrait on phones, so CrazyGames turns the phone and the 800 x 450 frame is never served to this game. Its FAIL in the audit is not a build task.
- "Games should land new users in gameplay immediately", one click at most. "The game interface is designed for the user's device."

## What the audit's frames show

At 907 x 510 a player with a mouse gets the phone layout: the top bar, the joystick and the round skill buttons over the map, the radial ring over a third of it (frames/907x510-wave10.jpg, 907x510-ring.jpg). At 1080 x 607 the Mode row is cut by the frame and Play solo is off screen (frames/907x510-home.jpg, 1080x607-home.jpg). A new player sees no way to start.
3. Text under 11 px in every desktop and tablet frame (AUDIT.md's notes name each selector).
