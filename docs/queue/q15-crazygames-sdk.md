## Why

## The SDK, from their docs (read by the advisor on 15 Nov 2026; a session may not be able to open docs.crazygames.com, so build from this and say in the pull request whether you could read the pages yourself)
- Loading: `<script src="https://sdk.crazygames.com/crazygames-sdk-v3.js"></script>` in the page's head, before the game's code. Then `await window.CrazyGames.SDK.init();` once: nothing else may be called before it resolves. The SDK is promise based; an error is `{ code, message }`.
- `window.CrazyGames.SDK.environment`: `'crazygames'` (on their site: everything works), `'local'` (on localhost or 127.0.0.1, or any address with `?useLocalSdk=true`: demo data, calls logged to the console) or `'disabled'` (any other address: every call throws).
- `SDK.game`: `loadingStart()`, `loadingStop()`; `gameplayStart()` when play begins or goes on, `gameplayStop()` at every break (a menu, the end of a match, a pause; not when the page loses focus: their site handles that); `happytime()` for a big moment, sparingly; `settings` = `{ muteAudio, disableChat }` with `addSettingsChangeListener(listener)` / `removeSettingsChangeListener(listener)` (the listener gets the new settings; `muteAudio: true` must silence the game whatever its own switch says).
- `SDK.game`, multiplayer: `isInstantMultiplayer` (boolean: the player asked their site for a multiplayer game, so the game goes straight into a room others can join); `inviteParams` (null, or the object a friend's invite carried) and `getInviteParam(name)`; `inviteLink(params)` returns a link to the game on CrazyGames that carries the params (treat the result as a string or a promise of one); `updateRoom({ roomId, isJoinable, inviteParams })` (any of the three; it is how their "invite friends" and "join" buttons know the room); `leftRoom()`; `addJoinRoomListener(listener)` / `removeJoinRoomListener(listener)` (the listener gets the invite's params when a player accepts an invite while the game is already open; a game opened by an invite reads `inviteParams` at start-up instead). `showInviteButton` / `hideInviteButton` are deprecated in favour of `updateRoom`: do not use them.
- `SDK.user`: `isUserAccountAvailable` (a property); `await getUser()` gives `{ username, profilePictureUrl }` or null for a guest; an auth listener fires when a guest signs in (signing out reloads the page). Their samples name it `addAuthListener(listener)` / `removeAuthListener(listener)`; the advisor could not confirm the names, so check `typeof` before calling.
- Their multiplayer rules for "Online with Friends": the room reported with `updateRoom`; with `isInstantMultiplayer` the first player lands in a new private room with default settings and is joinable at once; CrazyGames usernames shown in the game so friends know each other; a player who accepts an invite joins the room, and where a room cannot be joined (full, a match running) the game says so; friends stay together after a match. Anything players write needs a filter (q16 is that task, on the server).
- Their Automatic Progress Save copies an HTML5 game's localStorage to a signed-in player's account and restores it on their other devices. Their docs name localStorage only (IndexedDB only for Unity's PlayerPrefs) and give no way to leave a key out.
Do not use: ads, the data module, `getUserToken`, `showAuthPrompt`, account linking, the friends list, the profile picture.

## What to build
1. The script, in the crazygames build only. `hostedHtml` adds the tag above to the head for the crazygames host (the address a constant in embedHost.ts); the itch and newgrounds pages get no tag and never ask sdk.crazygames.com for anything. A new module under platform/ holds everything that touches `window.CrazyGames`, loaded by a dynamic import only in the crazygames build, with its rules in a pure module that is unit tested. The SDK is "on" only when the global exists, `init()` resolved and the environment is `crazygames` or `local`. `init()` is raced against 3 s. With the SDK off (the script blocked or slow, the zip served somewhere else) every call below is skipped and the build is today's linkless build, to the pixel. Every SDK call is wrapped: nothing the SDK does or throws may stop the game or show an error to the player.
2. Start-up. `init()` starts at the top of `main()`, beside the game view, never after it. The first screen waits for it at most 1.5 s behind the boot splash (so an invite or an instant start does not flash the home card first); a result that comes later still applies while the player has not started anything. `loadingStart()` once the SDK is on and `loadingStop()` when the first screen is interactive, always both, in that order, once a page load; the wait card before a match (V-08b load-all), when it shows, is `loadingStart()` … `loadingStop()` too.
3. Gameplay events. `gameplayStart()` when a match is on screen and running (solo, the lesson, the Daily run, a room's match, a rejoin) and when play goes on after a break; `gameplayStop()` at every break: the end card, leaving for the lobby, a lost connection's notice, and wherever the game's own sheet or card pauses a solo match (not the hidden-page pause). Never two starts or two stops in a row (a small state machine, pure, tested). `happytime()` once on a victory or a new Endless best, at most once a match.
4. Mute. While `settings.muteAudio` is true (read after init and from the listener) the game makes no sound, through the engine's own muted path, whatever ⚙ → Sound says; the player's own setting is not changed or stored, and comes back when it turns false. While it is on, ⚙ → Sound says "Muted by CrazyGames" in its box (11 px or more, no box changes size). `disableChat`: the game has no chat to disable (six fixed emotes, no free text); write that in SUBMISSION.md.
5. The name. Signed in to CrazyGames (`getUser()` gives a user; the auth listener updates it): the player's name in a room is the CrazyGames username, cut to the protocol's rules (`normalizeName`, at most 16 characters, cut on a whole character; if nothing valid is left, as a guest). The home card's nickname field shows it, not editable, labelled "CrazyGames name". It is never written to `tdt.name`. The boards' nickname fields work as today (when the stored nickname is empty they may start with the CrazyGames name, and the player sees and can change it before anything posts). A guest: the stored nickname as today; a guest with none who arrives by an invite or an instant start gets a made-up one ("Guest" and four digits, shown in the field, editable, stored only once edited). Never load or show the profile picture.
6. Rooms.
   - In a room (created, joined, rejoined): `updateRoom({ roomId: <the code>, isJoinable, inviteParams: { room: <the code> } })`. `isJoinable` is true while the room is in its lobby with a free seat, false when it is full or its match is running (a running match takes back only its own players, q12), true again when the room is back in its lobby with a free seat. Sent on a change only (a pure rule, tested). `leftRoom()` once when the player leaves the room or the room is gone. A solo match is never a room.
   - Opened by an invite: after init, the `room` param (through `normalizeRoomCode`) joins that room at once under the name of item 5, with no tap; a guest who needs to type nothing still joins at once (the made-up name). A refusal (`room_full`, `match_full`, `seat_recent`, a room that is gone) shows the home card with the reason in words, as today.
   - An invite accepted while the game is open (the join listener): from the home card or a room's lobby, leave the room if in one and join. In a running match (solo, the Daily run, a room's), a card inside the game asks once, "Join your friend's room? You leave this match." Join / Stay (the look of ⚙ → Match → Back to lobby's question). A match is never ended without that tap.
   - `isInstantMultiplayer` true after init: create a room at once as its host (the home card's mode and hero as they stand, the name of item 5), land on the room card, and report it joinable. An invite's `room` wins over an instant start; both win over the "Rejoin your match" offer (the remembered seat stays remembered).
   - The room card with the SDK on: **Copy invite link** is back and copies `inviteLink({ room: <the code> })` (a CrazyGames address, so the linkless rule holds: it never leads to a playable copy elsewhere), the code line stays under it ("or type this code in Join room"), an open seat reads "Open seat: invite a friend". With the SDK off: today's code-only card.
7. The data key stays in this browser. In the crazygames build `tdt.visitorKey` and `tdt.visitor` are kept in IndexedDB (one small store of the game's own), read into memory before analytics is installed (start-up is already async; at most 500 ms, then memory only) and written through. Everything that reads or writes the two keys goes through one `IdStore` (analytics, ⚙ → Your data, the boards' `x-data-key`, Delete my data); the site's build keeps `localIdStore` and its bytes. A key found in localStorage from the build CrazyGames holds today moves to IndexedDB and is removed from localStorage. With no IndexedDB the key lives in memory for the page's life: say in the pull request what that does to the counts and the boards. Every other key the game keeps travels as today (the settings, the record, the bests, the nickname, the age answer, the Play data switch, the posted marks, the first day, a remembered seat): list them in SUBMISSION.md with one line each, and say there that their docs name localStorage only, so IndexedDB staying out of their copy is what the docs say, not something a session could test.
8. The privacy page, in the `hosted` paragraph, in the page's plain words (the test lists both sentences): after the Automatic Progress Save sentences, "The data key that lets you download or delete your play data is kept apart, in this browser only: it is not part of that copy." And: "When you are signed in to CrazyGames, the game uses your CrazyGames username as your name in a room, as if you had typed it as your nickname." Nothing else on the page changes.
9. The build script and the harness. `build:embed -- crazygames` stops unless the page has exactly one SDK tag with the real address; `-- itch` and `-- newgrounds` stop if they have one. The browser test never loads the real SDK: `--e2e` points the tag at a stand-in shipped only in the e2e zip, a small script that gives `window.CrazyGames.SDK` with environment `crazygames`, records every call in `window.__cg.calls`, takes its start state from the frame's query (`cgUser`, `cgInstant`, `cgInvite`, `cgMute`, `cgInit=fail|hang|absent`) and can fire the listeners (`__cg.join({ room })`, `__cg.settings({ muteAudio })`, `__cg.login(user)`). A normal zip holds no stand-in (the script checks).

## Tests and checks
- Unit: the gameplay state machine, the room rule (what `updateRoom` is sent and when), the name rule (user, stored, made up, the cut to 16), the invite's code, the id store (IndexedDB faked: read, write, the move out of localStorage, memory only), `hostedHtml` per host.
- e2e/embed.spec.ts with TDT_EMBED_HOST=crazygames, in the projects CI runs it in: (a) a solo match: `loadingStart`, `loadingStop`, `gameplayStart`, then `gameplayStop` on the end card (`__tdt.lose()`), `happytime` after `__tdt.win()`, no call twice in a row; (b) a host's frame with `cgUser=Mira` creates a room: `updateRoom` with its code and `isJoinable: true`, Copy invite link gives the stand-in's link, the seat reads Mira; a second frame opened with `cgInvite=<the code>&cgUser=Bo` is in the room with no tap and both frames show both names; the match starts: `isJoinable: false`; a leave: `leftRoom`; (c) `cgInstant=1`: the room card with no tap, as host, joinable; (d) `cgMute=1`: the engine is muted, and `__cg.settings({ muteAudio: false })` gives the player's setting back; (e) `cgInit=absent`, `cgInit=fail` and `cgInit=hang`: the first screen still comes up (a hanging init costs the 1.5 s cap and no more), it is today's linkless card, a solo match plays, and no SDK call was made after the failure; (f) the join listener during a solo match: the Join / Stay card, Stay keeps the match, Join ends it and joins; (g) a `tdt.visitorKey` planted in localStorage before the load is gone from localStorage and in IndexedDB after it.
